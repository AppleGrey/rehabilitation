# 服务启动指南

在另一台机器上拉下代码后，按本文把本地开发用的一套服务全部拉起来。  
目标环境默认是 **Windows + PowerShell**；Linux / macOS 把路径和启动命令换成对应写法即可，端口不变。

## 1. 服务一览

| 组件 | 默认地址 | 说明 |
|------|----------|------|
| PostgreSQL | `localhost:5432` | 业务库 `rehabilitation` |
| MinIO | API `9000` / 控制台 `9001` | 视频与跟练录像对象存储 |
| core-svc | `:8081` | 用户、视频播放、方案落库 |
| admin-svc | `:8092` | 管理 API；代理 core / kg / ai |
| ai-svc | `:8000` | 问诊、方案、评估、视频库处理 |
| kg-svc | `:8010` | LightRAG 知识检索 |
| frontend-admin | `http://localhost:5173` | 管理平台（Vite 开发服） |
| Flutter App | — | 可选；`frontend/` |

管理平台默认走 **8092**，不要改回 8082（本机常见软件会占用 8082）。

## 2. 机器依赖

- Git、Docker Desktop（或等价 Docker 引擎）
- Go（跑 core-svc / admin-svc）
- Node.js + npm（跑 frontend-admin）
- Conda 环境 `rehabilitation`（跑 ai-svc），或自行建同名 Python 环境
- `kg-svc/.venv`（Python 3.11，跑知识图谱）
- FFmpeg（视频压缩 / 评估相关）
- Flutter SDK（仅在需要跑 App 时）

## 3. 拉代码与配置

```powershell
git clone <仓库地址> rehabilitation
cd rehabilitation
git checkout main

copy .env.example .env
copy kg-svc\.env.example kg-svc\.env
```

编辑根目录 `.env`，至少确认：

- `DATABASE_URL` / `DATABASE_ADMIN_URL`
- `MINIO_*`
- `JWT_SECRET`、`SERVICE_TOKEN`（core / admin / ai 三者必须一致）
- `SUPERADMIN_PHONE` / `SUPERADMIN_PASSWORD`（库里还没有超管时才会自动创建）

编辑 `kg-svc/.env`：

- 填入 `SILICONFLOW_API_KEY`
- 把 `KG_WORKING_DIR` 改成**本机绝对路径**，例如  
  `D:/codes/rehabilitation/kg-svc/LightRAG-KF-NEW/KangFu`

问诊 / 视觉 / 视频库处理的大模型密钥也可以先空着，等管理平台「配置管理」里再填；库为空时会用 `.env` 里的 `DEEPSEEK_*` / `DASHSCOPE_*` 灌一次。

## 4. 安装依赖（首次）

```powershell
# ai-svc
conda activate rehabilitation
pip install -r ai-svc/requirements.txt

# kg-svc
py -3.11 -m venv kg-svc\.venv
kg-svc\.venv\Scripts\python.exe -m pip install -r kg-svc\requirements.txt

# 管理前端
cd frontend-admin
npm install
cd ..

# App（可选）
cd frontend
flutter pub get
cd ..
```

Go 模块在各自目录下第一次 `go run` 时会自动下载。

## 5. 启动顺序

### 5.1 基础设施（PostgreSQL + MinIO）

```powershell
docker compose -f docker-compose.infra.yml up -d
docker exec rehabilitation-postgres pg_isready -U postgres
curl.exe -s -o NUL -w "minio %{http_code}`n" http://127.0.0.1:9000/minio/health/live
```

MinIO 健康检查返回 `200`、Postgres 显示 `accepting connections` 后再启后面的服务。  
若容器已在、只是没映射端口，删掉重建时务必挂回原来的 volume（`rehabilitation-postgres` / `rehabilitation-minio`），避免丢数据。

### 5.2 core-svc（8081）

```powershell
cd core-svc
$env:GOOS='windows'   # 仅 Windows 需要
go run ./cmd/server
```

日志里应出现 `postgres ready`、`bucket ready`、`listening on :8081`。

### 5.3 admin-svc（8092）

```powershell
cd admin-svc
$env:GOOS='windows'
go run ./cmd/server
```

日志里应出现 `listening on :8092`。

### 5.4 ai-svc（8000）

```powershell
cd ai-svc
$env:PYTHONUTF8='1'
conda activate rehabilitation
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

看到 `Application startup complete` 且 MinIO bucket 就绪即可。

### 5.5 kg-svc（8010）

在**仓库根目录**：

```powershell
$env:PYTHONUTF8='1'
kg-svc\.venv\Scripts\python.exe -m uvicorn app:app --app-dir kg-svc --host 127.0.0.1 --port 8010
```

首次加载图谱可能要十几秒；保持单进程即可。

### 5.6 管理平台前端（5173）

```powershell
cd frontend-admin
npm run dev
```

浏览器打开 <http://localhost:5173/> 。  
默认超管（仅库里还没有超管时会创建）：手机号与密码见 `.env` 的 `SUPERADMIN_*`（示例为 `13800000000` / `admin12345`）。

### 5.7 Flutter App（可选）

```powershell
cd frontend
flutter run --release
```

App 访问的后端地址按你们现有配置（模拟器 / 真机 / 代理）填写，需能打到本机的 `8081` / `8000`。

## 6. 自检

```powershell
curl.exe -s -o NUL -w "core %{http_code}`n"  "http://127.0.0.1:8081/api/videos?limit=1"
curl.exe -s -o NUL -w "admin %{http_code}`n" "http://127.0.0.1:8092/api/health"
curl.exe -s -o NUL -w "ai %{http_code}`n"    "http://127.0.0.1:8000/docs"
curl.exe -s -o NUL -w "kg %{http_code}`n"    "http://127.0.0.1:8010/health"
curl.exe -s -o NUL -w "ui %{http_code}`n"    "http://127.0.0.1:5173/"
```

期望：core / admin / ai docs / kg / ui 均为 `200`（个别健康接口若路径不同，以服务日志为准）。

## 7. 常见问题

1. **admin 登录 404、空响应**  
   多半是本机别的程序占用了 8082。本仓库管理端默认 **8092**，前端 Vite 也代理到 8092。

2. **core / admin 启动报连不上 MinIO `:9000`**  
   容器在跑但端口没映射到宿主机。用 `docker port rehabilitation-minio` 检查；不对就按第 5.1 节重建，保留 volume。

3. **ai-svc 启动时 MinIO 失败但进程仍在**  
   评估和视频处理会不可用。先修好 MinIO，再重启 ai-svc。

4. **kg-svc 路径错误**  
   `KG_WORKING_DIR` 必须是新机器上的绝对路径，不要照搬别人机器的盘符。

5. **超级管理员登不上**  
   种子账号只在「库里还没有任何超管」时创建，不会每次启动重置密码。

6. **Windows 控制台乱码 / LightRAG 崩**  
   启动 Python 服务前设置 `$env:PYTHONUTF8='1'`。

## 8. 不需要提交的内容

以下目录是运行期产物，不要进 Git，也不用从别的机器拷过来：

- `data/tmp/`
- `frontend/third_party/`
- `kg-svc/LightRAG-KF-NEW/**/kv_store_*_cache.json`（运行缓存）
- 根目录 `.env`、`kg-svc/.env`（密钥，用 example 在新机器重建）
